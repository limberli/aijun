=========
Changelog
=========

История изменений ``aijun-ui`` — AI JUN V2 workbench.
Формат основан на `Keep a Changelog <https://keepachangelog.com/ru/1.1.0/>`_,
проект придерживается семантического версионирования.

.. contents::
   :local:
   :depth: 1


[0.8.0] — 2026-06-16
====================

``aijun-ui`` — единственный интерфейс репозитория.

Changed
-------

- Старый интерфейс ``a2a-ui`` (Next.js + MUI) удалён из репозитория, чтобы не путать
  пользователей двумя UI. ``aijun-ui`` встроен во все compose-стеки на ``:5173``:
  ``VITE_PLAN=local`` для ``docker-compose.yml`` / ``-simple`` / ``-qwen`` и
  ``VITE_PLAN=free`` для ``docker-compose-groq.yml``. Избыточный
  ``docker-compose-groq-ui-v2.yml`` удалён (роль перешла к ``docker-compose-groq.yml``).
- ``run.sh`` / ``run.bat`` и вся документация (README, ``docs/DEVELOPMENT.md``,
  ``docs/LOCAL_GPU.md``) переведены на ``aijun-ui`` (``:5173``).


[0.7.0] — 2026-06-16
====================

Режим локальной модели — без намёков на оплату.

Added
-----

- **Режим ``local``** (``VITE_PLAN=local``) для самостоятельно развёрнутой модели
  (Ollama / ``docker-compose-qwen.yml``). В шапке вместо «Тариф: …» — бейдж
  **«Local model»** с иконкой ``Cpu`` (зелёной), чтобы не пугать оплатой.
- Экран тарифа в режиме ``local`` показывает отдельную карточку «Локальная модель»:
  без оплаты, без лимитов, данные не уходят в облако — вместо сравнения Free/Pro.
- Сервис ``aijun-ui`` добавлен в ``docker-compose-qwen.yml`` (порт ``:5173``,
  ``VITE_PLAN=local``) — локальный GPU-стек поднимается сразу с V2-интерфейсом.
  Заметка в ``docs/LOCAL_GPU.md``.

Changed
-------

- В ``PlanConfig`` добавлен флаг ``billable``. Все CTA про покупку токенов («Купить
  токены» в баннере лимита и на экране тарифа, пакеты на экране биллинга) скрыты
  при ``billable=false``. Экран ``billing`` в режиме ``local`` показывает пояснение
  «токены покупать не нужно».
- ``.env.example`` документирует ``VITE_PLAN=free|pro|local``.


[0.6.0] — 2026-06-16
====================

Покупка токенов перенесена внутрь приложения — без прямых ссылок на провайдера.

Added
-----

- **Экран «Покупка токенов»** (``components/BillingScreen.tsx``, маршрут ``billing``):
  пакеты токенов, плейсхолдер баланса, заготовка под оформление. Заглушка —
  реальный платёж появится с биллинг-бэкендом (Phase 2). Замысел: все покупки идут
  через наш сервис, аккаунт у провайдера пользователю не нужен.
- **Навигация без prop-drilling** (``lib/navigation.tsx``, ``NavigationProvider`` /
  ``useNavigate``) — чтобы из баннера лимита и экрана тарифа открывать биллинг.

Changed
-------

- Убраны **прямые ссылки на Groq** (``console.groq.com``). Кнопки «Повысить тариф» /
  «Купить токены» в экране тарифа и в баннере лимита теперь ведут на внутренний
  экран ``billing``. Поле ``upgradeUrl`` удалено из ``config/plan.ts``.

Phase 2 (план)
--------------

- Биллинг-бэкенд: платёжный провайдер, аккаунты, учёт и списание баланса токенов,
  наш ключ провайдера на сервере. Тогда экран ``billing`` получит реальные цены,
  баланс и оформление.

[0.4.0] — 2026-06-16
====================

Обработка лимитов LLM-провайдера на стороне UI + задел под тарифы free/pro.
Бэкенд не изменялся.

Added
-----

- **Блокировка генерации при лимите.** При ответе оркестратора 503 / ``AGENT_UNAVAILABLE``
  кнопка «Сгенерировать»/«Проанализировать» становится недоступной, и рядом
  показывается баннер с обратным отсчётом. Состояние общее для всех инструментов
  (лимит Groq — на уровне аккаунта), хранится в ``RateLimitProvider``
  (``lib/rateLimit.tsx``).
- **Точный или оценочный отсчёт.** ``a2a.ts`` кидает типизированный
  ``AgentUnavailableError`` (``lib/api/errors.ts``) и пытается вытащить время сброса
  из текста ошибки («try again in 26m53s» / «retry-after: N»). Если время известно —
  показывается точный отсчёт; если нет — оценка по тарифу (``estimatedCooldownMs``).
- **Различение причины.** Баннер показывает «Исчерпан лимит тарифа …» только при
  реальном rate-limit; при прочих сбоях агента — «Сервис временно недоступен».
  Кнопка «Повторить сейчас» сбрасывает блокировку вручную.
- **Конфиг тарифа** (``config/plan.ts``, ``VITE_PLAN=free|pro``): подписи, ссылка на
  апгрейд (free) и fallback-кулдаун. Это пока только UI-уровень — реальный лимит
  определяется аккаунтом Groq на бэкенде.

Backend patch (теперь точный отсчёт работает)
----------------------------------------------

- Сделан backend-патч, пробрасывающий причину и время сброса до UI (см. корневой
  ``CHANGELOG.rst``): агенты возвращают **429 + ``Retry-After``** с текстом Groq,
  оркестратор форвардит ``Retry-After`` и поля ``rateLimited`` / ``retryAfterSeconds``
  в теле 503. Фронт читает заголовок (приоритет) и поля тела.
- ``a2a.ts`` обновлён: ``describeError`` использует ``Retry-After`` и поля тела,
  текстовый парс — как запасной.

Verified
--------

- Проверено вживую на исчерпанном лимите Groq: ответ 503 с ``Retry-After: 1271``,
  телом ``rateLimited=true, retryAfterSeconds=1271``; заголовок доходит и **через
  Vite-прокси**. UI показывает «Исчерпан лимит тарифа Free» с точным отсчётом и
  блокирует кнопку. Ответ быстрый (~4.5с — fail-fast вместо таймаута оркестратора).


[0.3.0] — 2026-06-16
====================

Реструктуризация меню и выделение **«Анализ требований»** в отдельный инструмент.
Бэкенд не изменялся.

Added
-----

- **Новый инструмент «Анализ требований»** (``Написание документации``):
  отправляет требования с ``riskAnalysis=true`` и показывает отчёт аналитика —
  полнота, противоречия, неоднозначности, матрица рисков, тестопригодность,
  рекомендации. Выявленные риски выводятся отдельным блоком с уровнем.
- ``parseRequirementsAnalysis`` в адаптере: режет отчёт аналитика на секции
  ``## 1..6`` (заголовки фиксированы в промпте), переводит их названия на русский,
  переиспользует парсер Risk Matrix для списка рисков. Типы ``ReportSection`` и
  ``RequirementsAnalysis`` в ``types/result.ts``.
- ``components/ui/Markdown.tsx`` — лёгкий рендер markdown-подмножества (таблицы,
  списки, ``**жирный**``, абзацы) без новых зависимостей, для тел секций отчёта.

Changed
-------

- **Меню перестроено под структуру v0.3** (``config/menu.ts``):

  - ``Построение процессов`` — 4 под-инструмента (все «в разработке»):
    Тест-стратегия, Тест-план (IEEE 829 / ISO 29119), Матрица покрытия требований,
    Оценка трудозатрат.
  - ``Написание документации`` — Анализ требований ✅, Генерация тест-кейсов ✅,
    Генерация чек-листов (в разработке), Генерация баг-репортов (в разработке).
    Пункт «Тест-план» переехал в ``Построение процессов``.
  - ``Инжиниринг`` и ``Коддинг`` оставлены как категории «в разработке».

- **Из инструмента тест-кейсов убран тумблер «Анализ рисков»** — теперь это
  отдельный пункт меню. ``Workbench`` всегда шлёт ``riskAnalysis=false``.
- ``RequirementsPanel`` обобщён: вход (требования + загрузка) + слот настроек +
  кнопка с настраиваемой подписью. Контролы техник вынесены в ``TestCaseSettings``;
  используются обоими инструментами.

Fixed
-----

- ``a2a.ts`` теперь показывает осмысленное сообщение об ошибке: читает тело ответа
  оркестратора (``{ code, message }``) вместо голого «HTTP 503». Для 503 добавлена
  подсказка о вероятных причинах (лимит LLM-провайдера / упавший агент / открытый
  circuit breaker). Раньше пользователь видел только код статуса.

Verified
--------

- ``parseRequirementsAnalysis`` проверен на реальном ответе аналитика: 6 секций
  с русскими заголовками, 3 риска из Risk Matrix, fallback не потребовался.
- Диагностирован 503 при анализе: дневной лимит токенов Groq (TPD 100k) исчерпан
  → агенты отдают 500 → открывается CircuitBreaker → 503. Не баг фронта.

Notes
-----

- Инструмент «Анализ требований» вызывает оркестратор, который **всё равно**
  запускает tester-агент — тест-кейсы генерируются, но игнорируются. Устранение
  этой лишней работы требует правок бэкенда (Phase 2).


[0.1.0] — 2026-06-16
====================

Первый каркас нового интерфейса. Уход от чат-метафоры ``a2a-ui`` к инструменту
(tool) с главным меню и отдельными рабочими экранами. Бэкенд не изменялся.

Added
-----

**Каркас проекта**

- Новое приложение ``aijun-ui`` рядом с ``a2a-ui``: Vite + React 19 + Tailwind v4
  + framer-motion + lucide (зеркало стека ``aijun-web``).
- Палитра и шрифты AI JUN через ``@theme``-токены в ``src/index.css``
  (``ink``, ``surface``, ``brand-cyan``, ``brand-blue`` и т.д.).
- Алиас ``@/`` → ``src/``; конфиги ``tsconfig.*``, ESLint, Vite.

**Контракт данных и адаптер**

- ``src/types/result.ts`` — JSON-контракт ``AnalysisResult``
  (``cases[]``, ``techniques[]``, ``risks[]``), на который завязан весь UI.
- ``src/lib/parseAggregated.ts`` — **временный** адаптер (Phase 1): единственное
  место, знающее про markdown. Режет агрегированный ответ оркестратора по
  ``--- ## Risk Analysis``, парсит таблицу тест-кейсов (строка-заголовок ``TC-NNN``
  + строки-продолжения с пустой первой ячейкой), извлекает применённые техники и
  эвристически — список рисков с уровнем (high/medium/low).

**Транспорт (бэкенд не тронут)**

- ``src/lib/api/a2a.ts`` — JSON-RPC ``message/send`` к оркестратору; настройки
  генерации и тумблер рисков уходят в ``metadata: { qa, riskAnalysis }``.
  Без стриминга, отмена через ``AbortSignal`` (генерация может идти минуты).
- ``src/lib/api/extractText.ts`` — загрузка ``.docx`` → ``POST /api/extract-text``.
- ``src/lib/api/getModes.ts`` — схема техник из ``GET /api/modes`` с фолбэком на
  ``src/config/modes.ts``.
- Все вызовы идут через Vite-прокси ``/a2a`` → оркестратор (обход CORS без правок
  бэкенда). Цель прокси настраивается через ``ORCHESTRATOR_URL``.

**Интерфейс**

- Стартовое меню ``MainMenu`` по структуре V2 (``src/config/menu.ts``):
  Построение процессов / Написание документации / Инжиниринг / Коддинг.
  Активна только «Генерация тест-кейсов» → открывает workbench; остальные пункты
  с бейджем «в разработке».
- Workbench (``src/components/workbench/``):

  - слева — поле требований, загрузка ``.docx``, переключатели техник/типов и
    тумблер «Анализ рисков»;
  - справа — тест-кейсы как аккордеоны (раскрываются в таблицу шагов
    «# / Шаг / Ожидаемый результат» + кнопка «Копировать»);
  - снизу ``StatsBar`` — число кейсов за прогон, применённые техники и
    граничные случаи, число рисков (если включён анализ рисков).

- Примитивы UI (``Panel``, ``Badge``, ``Button``), оболочка ``Shell``
  (фон-свечение + шапка), state-based навигация меню ↔ workbench в ``App.tsx``.

**Инфраструктура**

- ``docker-compose-groq-ui-v2.yml`` в корне репозитория — поднимает весь бэк
  (Groq) + ``aijun-ui`` в dev-режиме на ``http://localhost:5173``.

Fixed
-----

- ``parseRisks`` теперь читает таблицу **«Risk Matrix»** из отчёта аналитика
  (колонки ``Description``/``Severity``) вместо наивного подсчёта всех буллетов —
  иначе число рисков завышалось за счёт пунктов «Ambiguity», «Recommendations»
  и т.п. Severity ``Critical/High`` → high, ``Medium`` → medium, ``Low`` → low;
  сопоставление колонок по заголовку (устойчиво к смене их порядка). Если матрицы
  нет — мягкий фолбэк на буллеты.

Verified
--------

- Сквозная генерация проверена вживую на работающем бэке (Groq):
  ``браузер → Vite /a2a → оркестратор → tester+analyst → markdown``.
  На реальном ответе адаптер корректно разобрал 21 тест-кейс (сквозная нумерация,
  группировка шагов) и 3 риска из Risk Matrix; fallback не потребовался.

Notes / Known limitations
-------------------------

- **Покрытие в %** намеренно не отображается: честного источника в бэкенде нет.
  Появится в Phase 2 (см. ниже).
- Прокси ``/a2a`` — фича dev-сервера Vite. Для прод-деплоя нужен reverse-proxy,
  пробрасывающий ``/a2a`` на оркестратор, либо CORS на бэкенде.

Phase 2 (план, не реализовано)
------------------------------

- Бэкенд отдаёт ``AnalysisResult`` как JSON (например, A2A ``data``-part) →
  удаляем ``parseAggregated.ts`` и его вызов в ``Workbench.tsx``, UI не меняется.
- Реальное покрытие в % (планнер уже извлекает список функций → покрыто/всего).
- Новые агенты-инструменты меню: чек-листы, баг-репорты, тест-план, трассируемость.
